# Frozen Web baseline contract

Authority: all appearance, animation and effects are defined by the frozen legacy source and its effective production call paths, subject to explicit user requirements and intentional migration differences. Screenshots, video, computed styles, runtime parameter exports and numerical golden samples are references for verification and diagnosis only. Rendering/backend/capture defects cannot redefine the source contract. Resolve disagreements by tracing source initialization, overrides, state, timing and shader algorithms; do not damage a correct native implementation to match a faulty capture.

The reference is commit `57f4f845c20cce646a15dbf4008c2a162aaaf4e2` (V0.4.1), music entry `src/main.ts → src/music-app.ts`. `legacy-web/` remains the asset and dependency source. Review code extracts that commit into ignored `build/web-baseline/legacy-web/`; it never edits the archived source or starts the old music service. The Vite/API fixture server binds to loopback, has no scanner, and returns only generated JSON. Browser storage and profile are isolated under `build/web-baseline/`. External page requests are rejected and reported. Audio and BGM are disabled.

Rebuild from the repository root:

```powershell
Push-Location legacy-web
npm ci --ignore-scripts --no-audit --no-fund --allow-remote=all
Pop-Location
node tools/review/export-web-baseline.mjs
node tools/review/check-web-baseline.mjs
```

`--allow-remote=all` is needed by npm 12 for the existing lockfile's tarball mirror URLs; this does not add packages or change the lockfile. The exporter verifies the lockfile against the frozen commit. No browser is downloaded. It discovers installed Chrome/Edge/Chromium or accepts `--browser=PATH` / `REVIEW_BROWSER`. `--repo-root=PATH` and `--web-root=PATH` are independent inputs. Build/check subprocesses run with the detached Web root as cwd and an explicit isolated `MUSIC_DATA_DIR`. Node is a review dependency; it is not a future native application runtime dependency.

`tests/fixtures/web-baseline/anonymous.json` is shared scene input: viewport, DPR, theme, quality, array mode, stable album IDs, selection, motion time and events. It contains empty/single/even/odd/mixed/480-album libraries, three bundled demo cover shapes, Chinese long titles, descenders, parentheses, emoji and combining characters. Roots are empty; synthetic tracks have no audio URLs. No user music, browser preferences, index or absolute music paths are read.

`source-map.json` enumerates every frozen `src/` module with content hash, imports, music reachability and new responsibility; service modules have separate scanner/provider/audio policies. Reachability includes shared archive geometry/shaders and the viewer; reference-only modules remain archived. `library-order.json` calls the frozen `setMusicAlbums/orderMusicAlbums` functions and records actual stable album IDs and column order for each fixture. Visual Qt fixtures must use this order rather than relying on platform collator differences. The new application must split composition, navigation, models, motion, rendering, media and offline metadata rather than transplant `music-app.ts` wholesale.

`scene-parameters.json` is a hash-checked index into `web-scenes/*.json`, which store final camera matrices, light world transforms, effective material properties, texture settings, compositor order and active AO/DOF/AA, instance transforms, paper geometry/UV, computed UI typography/layout/visibility/CSS variables and brand rectangles. State settles before capture. Values come from real initialized objects, not constructor defaults. Geometry and the shared fixed atlas UV layout are separately sampled from actual runtime objects. Invalid/missing required fields fail verification.

Review-only Vite transforms expose private JS object state and append an application frame driver. Production functions and rendering algorithms remain unchanged. The FPS HUD follows this synthetic clock and is not GPU or performance timing evidence. Frames and Web Animations advance at explicit 1/120-second intervals; actual animation completion promises/events are flushed between tasks. Rendering happens only at samples, with visible textures prepared and uploads flushed. Resource preparation uses readiness predicates; screenshot timing never uses a sleep as scene-state evidence. `motion-golden.json` calls frozen analytical functions for damping, quintics/rebase/reversal, real columns, ribbon motion/field, overview folding, glyph tracks and opening; 20/30/60/120-fps and long-frame inputs are recorded. Each numeric sample specifies dt and events; events apply before that input frame update. Glyph start/velocity/target, spring rates and retarget/rebase inputs are explicit. `presentation-golden.json` samples the actual application switch/reverse/back sequence at 1/120 second, including camera and returning-copy state.

`docs/media/web-baseline/screenshots.json` identifies each fresh PNG by baseline, fixture hash, browser/GPU, viewport/DPR, quality, explicit time and event input. Nine sizes × two themes × both array modes are captured, plus detail/overview, representative DPRs, empty/small/large libraries, exact opening nodes and switching. PNGs contain only content pixels. These captures are historical visual references only. Do not run SSIM, RGB, edge-band or GPU-byte comparisons against them; verify source formulas, structure, behavior, resources and actual native quality separately. These files do not claim Qt equivalence.

`room-environment.json` records the actual `RoomEnvironment.toJSON()` input, PMREM sigma, dimensions/format/mapping and a hashed GPU readback. `room-pmrem.rgba16f` is tightly packed RGBA half-float, little endian, in WebGL render-target row order (bottom row first). This is a historical cube-UV PMREM sample. Its bytes are not an acceptance oracle; the environment algorithm, orientation, effective production input and precision must be reviewed from source in R19C.

Intentional native differences: ordinary QtMultimedia sequential playback replaces gapless/PCM/Swift/CoreAudio routes; networking is deferred while provider/source/cache fields remain; archive/PWA/browser-only entry points are excluded. The original brand is preserved in this reference and replaced by R03B's SVG in production. Brand container position, timing and adjacent UI remain source-defined layout and behavior targets; there is no original-image pixel-comparison gate. Network/audio simplification is never a blanket GUI-difference exemption.

For a focused parameter/sequence refresh from an already verified screenshot index, use `node tools/review/export-web-baseline.mjs --refresh-contracts`; it verifies the same commit/fixture and scene hashes, replays opening/switching and regenerates numerical/environment inputs. A failed export removes the previous success report; it cannot pass the checker using a stale report.

Visible stair-step edge aliasing in these Web captures is a baseline rendering defect, not a reproduction target. The exported original preset has SMAA disabled; this observation does not by itself identify every source of aliasing. `web-baseline-defects.json` registers the defect. Qt must provide effective edge smoothing without shifting geometry or softening artwork with global blur. Inspect the native renderer’s own output for smooth, clear contours, tracing defects to source geometry, sampling and composition; do not create original-image differences or tune against jagged baseline pixels.


R19A separates the basic provenance check from capture reconstruction. `node tools/review/check-web-baseline.mjs` works directly from committed source/assets/numerical inputs and the cleaned frozen revision; it requires no browser, screenshot index, scene dump or GPU readback. It validates archived source hashes, original/prepared resource hashes, branding and anonymous/numerical input constraints, and prints its scoped result without writing a success report. Run `export-web-baseline.mjs` only when reference capture/reconstruction itself is needed; its capture success never certifies native source fidelity. Component-specific legacy comparison removal belongs to the explicit R19B–R19G owners in [source-fidelity-review.md](source-fidelity-review.md).
