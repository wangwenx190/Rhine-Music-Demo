# 性能设计、审计与验证契约

本契约是性能验证策略的唯一权威，约束所有剩余轮次及后续维护。优先从架构设计、算法设计和实际代码实现进行严格静态审计；只有实在难以从代码确定、且影响当前判断的具体问题，才进行最低程度、最小范围的实际测试。静态已能确定的结论不追加实测“再证明一次”；benchmark通过不能豁免设计或实现缺陷。完整功能和源码效果须保留，不能靠关闭效果、降低画质或改动歌曲/输入实现性能优化。

## 审计顺序与实测门槛

1. **架构设计**：展开真实生产调用链、模块职责、状态与资源所有者、GUI/render/worker边界、唯一时钟、队列及背压、取消/退出协议、缓存与失效关系、平台差异。核对设计是否引入重复工作、无界积压、隐式同步或相互等待。
2. **算法设计**：按实际输入上界推导初始化、单次操作与每帧的时间/空间复杂度、最坏工作量、临时内存及同时存活峰值；检查查找/排序/采样/批处理/增量更新是否合理。区分固定常量与随库大小增长的项，推演边界、反转、失效和错误路径，不能仅看平均情况。
3. **实际实现**：从真实入口沿调用、信号/绑定、线程交接直到绘制/上传/释放，核对算法是否确实被生产采用；检查循环、分配/复制/隐式detach、I/O、锁/等待、资源创建、缓存键及generation/epoch。覆盖正常、隐藏、取消、替换、失败和销毁分支；声明、helper或字符串命中不能替代实际执行路径分析。
4. **静态结论**：给出关键源码符号、推导依据、适用输入/平台及假设，区分“静态已确定”“发现缺陷”“仍无法确定”。源码可确定的缺陷直接修复，不先跑benchmark。复用仍有效的审计，只补受影响链路；不为局部修改重做全部矩阵或增加独立报告体系。
5. **最小实测**：仅对仍无法确定的具体问题，先说明代码为何不足、需要观察什么，以及哪种结果能作出判断。选择能回答该问题的最小输入、单个相关操作/资源所有者/后端和最短必要观察过程；不以改变原画质/效果或绕过待证明边界缩短测试。优先复用已有证据或一次正常回放中的观测，结论足够即停止。只有实际差异、歧义或失败才追加对应边界，不展开完整主题/DPR/平台矩阵，不默认计时、暖机、压力或重复批次。

实际Qt调度、驱动行为、硬件耗时和系统资源驻留可能无法由源码确定；这不自动产生测量义务。仅在这些事实影响当前具体问题或明确验收要求时最小实测；否则保持未知或注明静态估算，不能声称获得真实FPS/GPU时间/driver显存，也不因此挂起泛化的性能补验任务。构建、功能正确性、实际画质与物理设备事实的必要验证独立按test-gates.md选择，不借这些名义附带性能采样。

## 设计与算法的前置要求

实施前按上述顺序审查本轮修改及受影响的已有实现，不能仅查新文件。证据指向实际源码符号及相关内容版本；沿既有契约/审计记录维护必要结论，区分源码推导与真实运行事实。以下PERF-01–07是审计清单，不是七组必跑测试。

| 检查项 | 必须证明的设计性质 |
| --- | --- |
| PERF-01 工作量与复杂度 | 每帧只访问有界可见池和活动动画，不遍历全库；排序先生成每元素键，比较器不反复做归一化、矩阵乘法或 I/O；分组/稳定 ID 查询使用索引。注明最坏规模和临时内存，不能只用平均复杂度。 |
| PERF-02 线程与背压 | GUI 与 render 的热路径没有读盘、解码、等待 worker、手动转事件循环或每帧 GPU finish/readback。任务按稳定身份合并，generation 取消有效，解码中、待解码、完成缓存和待上传各自有界；队列不能靠无限积压来满足每帧限额。 |
| PERF-03 快照与增量更新 | 不可变值快照和 Qt 隐式共享用于交接；需要隔离外部像素时按内容 revision 复制一次。重复/过期结果在复制前淘汰。仅上传已写入范围；动画不重建模型、材质、纹理或完整实例池。 |
| PERF-04 渲染图与资源 | 展开 pass 的读写边、附件格式/大小/MSAA、resolve/mips、排序和 overdraw；目标与 PSO/SRB 仅在兼容性键改变时重建。可见数量、相机/焦点/灯光数值变化不能触发无关目标重建。每个资源有明确所有者和最后使用位置；复用仅发生于无重叠生命周期。 |
| PERF-05 等价算法与缓存 | 公共计算提升到每帧/每实体，缓存依赖完整且可失效；先剔除不可见工作，阴影 caster 不变时复用阴影，冻结几何共享实例化。对改变求值顺序/精度的变换单独验证，不能把近似算法称为等价。 |
| PERF-06 QML 与输入 | 委托/字轮/歌单虚拟化，文本测量按文本/字体/宽度缓存；信号批量提交，避免绑定连锁重算。拖动只发布最新目标，动作确认与视觉动画分开计时；隐藏/遮挡层不保留无效 tick、上传或可点击项。 |
| PERF-07 生命周期与平台 | hide/restore/resize/reload/退出的取消、释放、容量和缓存规则明确；无稳定增长、悬空回调或重复初始化。逐平台审查 D3D11/Metal/GL 的分支、格式/采样/限制与同步，动态运行后端按test-gates.md选择，Windows 成绩不能外推其他设备。 |

优先采用 Qt 已有的异步事件、worker、隐式共享、共享几何/实例缓冲、局部纹理传输、dirty revision、固定或按容量增长的缓冲、可追溯渲染图和资源池。不要为“更先进”引入另一套状态、任意多线程、全新引擎或第三方库。实例化减轻 CPU 提交，不自动解决片元/采样/带宽成本；光学壳体的全局 depth/ID/surface 顺序仍须保留。

效果数学、材质语义、颜色空间和时序沿冻结源码与用户指定差异；原生尺寸和生产采样质量唯一见occlusion.md/postprocess.md；调度、存储、索引、缓存、批处理与生命周期不要求复刻低效实现。替代方案必须说明适用条件、实现成本、兼容边界和源码效果差异，先从算法与真实实现证明几何、运动、颜色和材质等价；仍无法静态确定的具体输出差异才作最小功能/质量对照。Qt 模块的许可证类别、技术预览标签和较新的 API 不作为选型排除条件；以实际能力、效果/行为、资源/性能及实现维护成本判断，Qt Canvas Painter的API/资源规范由canvas-painter.md维护。降低采样数、近似透明、降低精度或分辨率属于效果变更，不能自动纳入性能修复。

## 主项目算法与存储审查结论

范围为`main`组合的生产C++、平台适配、QML与shader调用链；Review、测试、工具和脚本不属于本次代码审计对象。以下为源码可确定的性质，不表示取得FPS、GPU耗时、driver驻留或其他目标系统的实际运行事实。N/R为远端曲目数/其中重复标题的曲目数，V/D为当前视觉树项数/深度。

| 调用链 | 静态结论与适用边界 |
| --- | --- |
| LibrarySession → LibraryModels → 面板/DetailModel | 库边界建立身份/流派/浏览位置索引；排序键一次生成，比较器不解析文本。交互搜索复用文本索引，单worker与最新查询按generation背压；空查询整段跳过曲目。委托虚拟化，制作人员按当前专辑分组；没有按视觉帧遍历全库的生产路径。具体成本归library-data.md。 |
| DirectoryScanner / LegacyImporter / MediaMetadataProbe | 扫描使用显式目录前沿，逐目录预生成自然排序键；根直属单曲图片按文件名索引。导入目的路径逐级解析已有祖先，再一次拼接未存在后缀，不使用原生递归栈。探测复用两个媒体槽，纯缓存游标分批让出事件循环；读盘、解码和保存仍在所属worker。 |
| MetadataWorker → MusicBrainzSource | 唯一标题平均O(1)哈希定位；只为重复标题建立四种可选disc/position投影，连续排序数组和迭代压缩的后继索引跳过已用候选。按哈希平均查找计，索引建立O(N+R log R)，匹配保持O(N+R log R)摊还上界及O(N+R)存储（另计字符串比较/规范化）；没有同名桶反复扫描或逐投影树节点分配。只接纳唯一候选，时长边界继续使用原绝对差判定；状态/来源/上限归library-data.md。 |
| InputRouter / TrackList | 输入命中与曲目布局均使用显式祖先栈，逐项访问并保留裁剪/祖先归属或子先父后/兄弟顺序；常见输入深度使用内联栈空间。栈帧数O(D)，没有C++/JS深度递归；Qt坐标转换仍有自身祖先链成本，不将一次访问误称总成本必为O(V)。布局仅处理已实现视觉项，不展开全部歌曲。 |
| SelectionController → ArchivePool → SceneAdapter → RHI | 固定池单次遍历，同列坐标/列查找每列一次；场公共量、相邻采样、相机矩阵与实体光场按现有依赖复用。真实列延迟采样，实例暂存/上传缓冲保留容量；opaque/shell排序先生成depth键。固定控件/表面/通道/像素邻域的多重循环各有独立维度，不能仅展开循环或降低采样数来声称算法优化。 |
| CoverCache / SceneCovers / 媒体 / 偏好与显示 | 图片LRU使用哈希与链表，重放/租约/generation控制复制与失效；静态shader、几何、颜色端点和曲线由函数级缓存持有。选中/归位、媒体探测和界面声音复用既有有界池；普通播放队列按快照复用曲目/ID索引。偏好保存合并最新值，显示通知合并后查询；无需另加无界对象池、静态QObject或跨线程可变缓存。 |

没有需要计时才能决定的具体性能未决项。独立后端、部署与设备能力缺口继续由迁移计划R36按原门槛管理。

## 预算的来源与适用范围

实体池/副本容量由[archive-pool.md](archive-pool.md)维护，解码/缓存/上传字节由[covers.md](covers.md)维护，实际RHI布局由[rhi-postprocess.md](rhi-postprocess.md)维护，目标尺寸/生产采样由[occlusion.md](occlusion.md)维护。本契约定义推导和解释方法，不另复制一套数值。上限不是必须用满的工作量；请求上传字节不是物理总线流量，缓存计费不是完整进程/driver驻留内存。

沿实际代码静态列出产品资源清单：每个目标、图集、选中/归位纹理、buffer、lookup、Qt 输出及 resize 旧/新资源的同时存活峰值。估算为各资源实际尺寸×每像素字节×样本数，再加 resolve、mip 链及非图像资源；共享附件只计一次。估算值与实际 API/系统可获得的测量值分别标记，不把估算当显存实测。

例如单张 RGBA16F 在 1920×1080 为 15.82MiB，4× MSAA 颜色附件为 63.28MiB，resolve 另计；3840×2160 对应 63.28MiB 和 253.13MiB。单个目标尺寸不足以约束多通道峰值。产品必须在分配前验证格式、尺寸、采样、累计资源计划与错误路径，明确提示无法支持的配置，不偷偷保存较低画质。没有设备依据时不得编造一个通用显存硬上限。

## 三类验证及结论边界

1. 静态审计是默认方式：确定复杂度、线程/所有权、队列上界、失效条件、资源图、等价性及平台分支；满足相关性质即可形成静态结论，不附带benchmark。
2. 局部诊断只补静态未决问题：仅观察需要区分的GUI/同步、提交、GPU pass、上传/解码或释放行为，不自动全部采集；结论限定于该问题。
3. 产品实际检查只证明代码不能替代的事实：例如具体环境的调度/呈现异常或资源是否真正释放。使用相关真实路径，最小回放即可，不自动建立完整播放器性能基线。功能和画质另按各自要求验证。

正常VSYNC采样须从子进程环境移除`QSG_NO_VSYNC`；Qt按变量存在性处理该开关，空字符串同样禁用VSYNC。未限速采样才设置它，并记录`QWindow::requestedFormat().swapInterval()`；请求值不能证明实际显示同步。[Qt实现依据](https://github.com/qt/qtdeclarative/blob/dev/src/quick/scenegraph/qsgdefaultcontext.cpp)。

CPU 提交不包含同步阶段或 GPU 完成时，报告必须明确。GPU timestamp 不可用写 null/不可用，不能写 0 或用 CPU 值替代。frameSwapped 是 Qt 呈现事件，不是屏幕实际扫描时刻；输入延迟仅统计采样期间实际收到的事件，静止场景无新输入时保留空分布；原始单调时刻与自身窗口曝光/可见/状态变化分别保留，采样期间失去曝光判为无效；关闭 VSYNC 的吞吐、正常 VSYNC 下的节奏与系统 compositor/显示延迟分别报告。窗口置底、遮挡或系统节流导致无样本时判定测量无效，不伪造性能失败或提高窗口 Z 顺序。

## 按需测量与结果解释

- 常规性能验证先完成严格静态分析；实际功能回放暴露卡顿、迟滞或资源增长时，也先沿代码定位。只有余下问题仍难以静态确定才最小实测；不要求固定时长采样、额外暖机、完整矩阵或重复批次。必需资源就绪是执行条件，不另设暖机流程；准备本身若是问题则直接分析/观察。
- 既有1920×1080原始画质、120秒、p95≤20ms、p99≤两个刷新周期及>50ms统计，仅在明确采用该可选协议的性能专项中解释，不自动扩展到其他场景/设备或成为收尾前置。普通回放可以记录已有遥测；短样本不宣称长期稳定性，也不因不足120秒而失败。
- 性能设计参考刷新率为60Hz；高刷屏实际刷新率单列，不能自动把120/144Hz屏幕变成所有画质都须达到120/144fps的门禁。额外高刷目标先声明设备/质量/目标周期；分位跨周期边界的微小偏移须结合测量分辨率和固定复核批次解释，不通过任意扩大容差放行持续卡顿。
- 响应问题先审查事件收到→状态交付→帧提交的实际代码。仅调度/提交时序仍有疑问时观察所需节点；无需为每个输入建立延迟基线。实际显示时刻不可测时保持未知，不从帧间隔反推input-to-photon。
- 资源准备与冷启动先分析阻塞点、依赖顺序、工作量及队列/内存上界。只有具体等待、峰值或交接行为无法确定时才定向观察；不固定收集所有阶段时延。交互期间的真实长帧不能以“准备中”名义排除。
- 最小实测的范围、输入、停止条件由静态未决项决定；需要计时时再按问题出现周期选观察长度。A/B比较保持同Kit、设备、输入和画质，仅有歧义才追加所需对照，不预设三次。保存实际样本与失败，不池化或挑最快一次；采样不与构建或其他GPU工作并发。
- 采集驱动按真实帧/输入事件发布一次状态，通过Qt正常事件循环等待结束；不能以毫秒轮询重复submit/验证同一实例池，再用手动processEvents/msleep驱动呈现并将唤醒/轮询成本混称GPU吞吐。测量协议改变时旧/新结果分别保留，不能把驱动改进的帧率变化归因于渲染算法。
- 异常先检查有效性和对应事件；需要区分环境干扰或检验修复时只重放相关问题，不自动追加固定复核批次或扩大场景。无法解释的实际失败保留为该问题待办，不用无关运行冲销，也不无限重跑直到通过。结构错误、持续卡顿和资源增长须修复。
- 历史数字没有足够设备/体验依据时标明适用范围，补齐测量入口。调整数字必须有预算推导、前后全样本、体验影响及变更理由；不能因为实现过不了而放宽，不能把无来源的更低数值硬塞到每轮阻塞开发。新增指标先建立有效测量；尚未实现的产品路径保留所属轮次任务，不冒充已验收。
- CPU 与 GPU 是流水线，不能将两个分位简单相加推导帧时间。p95/p99、卡顿计数、输入延迟、资源峰值和就绪时间各自解释；更低 CPU 开销不自动宣称 FPS 提升。

## 可选计时协议与退出模式

`YALAHOO_PERFORMANCE_RECORD_ONLY`只控制Review性能退出；functionalPassed/samplingComplete/gateEnforced与原数值结果分别报告。只记录模式不能覆盖功能失败，也不能将超预算改写为达标。当前是否需要计时及采用哪种协议，仍须满足本契约的静态未决条件或用户明确要求；历史专项不产生重复采样义务。

离屏GUI线程sync/render、CPU提交、offscreen endFrame等待分别记录，不替代呈现/VSYNC或产品threaded性能。

## 可选场景与记录

产品场景包括稳定静止/活动波浪、快速首尾与反向浏览、真实列/填充切换、抽取/归位/三次换片、总览和面板滚动、搜索连输/取消、大封面与扫描快照交接、主题/画质/resize/DPR、hide/restore 和重建。使用已有匿名 fixture，覆盖空/单/奇偶/长短列、超过432库与96张合成大封面。当前固定生产质量下按问题选择主题、尺寸/DPR；大输出的资源成本与普通桌面分开解释，不将所有设备强行套用同一1080p时长/刷新门槛，资源性质仍须按本契约静态审计，实际压力仅由具体未决问题触发。

每轮先完成PERF-01–07适用的架构、算法及实现静态审计。首次设备/后端、修改性能代码、阶段收口都不自动触发实际性能测试；只有上述审计留下影响当前判断的未决项，或用户明确指定实测时，才选择最小入口。功能/输出/物理事实另按test-gates.md验证，不增加性能基线。

Linux的X11/Wayland分别完成实际窗口/输入/呈现检查，不为会话切换附加计时矩阵；某会话出现具体问题时只调查该会话和相关操作。

证据在本地生成目录或单独归档中保存，按 `verification-artifacts.md` 执行，不提交原始序列、截图、日志或机器产物清单。保留场景/hash、源码/二进制 hash、Qt/编译器/OS/GPU/后端、逻辑/物理尺寸/DPR/render scale、质量、刷新/VSYNC/窗口策略、暖机/持续时间、测量范围与失败原因；仓库只保存必要契约与简明结论。工具遵守测试窗口契约；采集自身渲染结果，不采集桌面。

## 官方实现依据

- [Qt Quick 性能建议](https://doc.qt.io/qt-6/qtquick-performance.html)：异步、worker、避免阻塞和实际 profiling。
- [Qt 隐式共享](https://doc.qt.io/qt-6/implicit-sharing.html)及[线程与隐式共享值](https://doc.qt.io/qt-6/threads-modules.html)：值副本的共享/写时分离不等于允许多个线程修改同一个对象。
- [QQuickRhiItemRenderer](https://doc.qt.io/qt-6/qquickrhiitemrenderer.html)：同步阶段 GUI 被阻塞，QRhi 资源属于渲染侧；不能在同步中重复大量深拷贝。
- [Qt Quick 3D 实例化](https://www.qt.io/blog/qtquick3d-instanced-rendering)：批处理收益与排序/overdraw 的适用条件分别判断。

执行时核对所选最新 Kit API；上述链接不锁定 Qt minor/patch。

## 实验面板的运行诊断

`SceneItem.diagnosticsEnabled`独立于Review的完整`telemetryEnabled`；面板仅开启前者。render每次正常提交记录固定标量：从资源准备到提交尾部的CPU耗时、同步CPU耗时、QRhi最近完成GPU帧时间、三类请求上传字节与单调提交时刻。关闭时不启动相关计时；没有额外render/readback/GPU finish。帧间隔使用未钳制的单调时间，不使用FrameClock的运动dt。

每类保留最近256个样本，以nearest-rank计算p50/p95/p99，超容量计数单列；每至少500ms形成一批，固定邮箱仅保留最新批和一个GUI通知。GUI按批读取解码启动累计/活跃/等待计数并更新小型显示值，SceneItem在C++形成诊断展示文本，不序列化全库或逐帧JSON。原生`frameSwapped`发出时直接记录单调时刻至同一有界邮箱，不能用GUI排队到达时间当作呈现事件间隔。隐藏/最小化/关闭/换窗口清空基线、断开事件并用epoch拒绝旧结果；Review显式RenderControl目标可采提交，但没有原生呈现样本。

面板的“提交吞吐”是该批间隔数/时间，反映当前调度与等待，不宣称未限速benchmark；CPU同步与提交分别列出，不相加分位；GPU范围为QRhi后端提供的已完成帧，缺样本显示不可用。VSYNC只显示请求swapInterval，实际VSYNC、屏幕扫描时刻及input-to-photon均不可用；零上传是有效计数，空时间样本不能显示为0。

## 冷启动与产品回放入口

`startup`核对准备/Film快照门槛、隐藏最新值合并、恢复首间隔与帧内失效。`startup-qml`（`ui-tests --startup 新目录 [0或12..120秒] [matrix或固定场景名]`）加载真实MusicStage；普通回放覆盖三次换片、缓存回选、暂停/播放各一次完整视觉root/SG重建、源revision/意图保留、renderer释放及资源回落。滑尺往返、文字、总览、搜索、序章重播/跳过、主题/DPR/resize仍走真实组件；隐藏、空闲零工作需要观察窗口，不以立即检查代替。匿名输入为9×64专辑、96张独立2048² JPEG、qrc封面和静音合成WAV，禁止私人库。

`verify-startup.py --observe-only --mode vsync|uncapped --scenario day-wave|night-wave --seconds 12..120`只观察一个原生波浪场景：同一576专辑/有界实体池使用qrc封面，无歌曲、大封面生成、功能回放、换片、root重建或固定暖机，不能与formal合用。底层为`ui-tests --startup 新目录 秒数 场景 observe`。只记录真实FrameClock帧回调、afterSynchronizing、RHI提交、frameSwapped及窗口事件；一个时限timer结束观测，不驱动渲染或轮询。三个原始时间流须在采样区间内有递增样本，持续曝光与窗口策略独立验收；短观察不执行长期性能门槛，不解释历史异常为已修复。`samples[].clockFrame`是在GUI接收遥测时读取的计数，精确GUI时序使用独立`guiFrames[].atNs`。

普通功能回放覆盖换片和暂停/播放各一次完整root重建，记录实际次数及释放/恢复结果。短采样、离屏、未限速结果不写正式呈现通过，包装工具以`formalRequested/formalAcceptancePassed`区分；正式批次保留每次失败及原始样本，不自动追加新批次直到通过。

计时入口除observe-only外仍先执行完整功能回放；仅具体未决问题确需这些输入时使用。单独的同窗口事实使用上表最小入口，不附带大封面、换片或root重建。

工具提供的`day/night`与`wave/ruler/detail/switch/overview/search`是问题定位选项，不是必跑清单。按问题选择所需场景，不能将其展开成十二项长采样；混合`matrix`也不产生正式性能结论。窗口策略按test-window-policy.md；原生frameSwapped在实际发出点计时，样本不足或曝光丢失时如实说明测量限制。

本机RenderControl分别报告GUI polish、beginFrame、sync、Quick render、endFrame等待和RHI CPU/GPU成本，异步就绪等待由真实事件唤醒，手工回放按请求60Hz推进既有FrameClock；不声称产品threaded或正常呈现。仅保留本次未决项实际需要的样本/计数和失败信息，按verification-artifacts.md存放本地；driver显存/物理输入/屏幕扫描不可测保持null。原生生命周期使用匿名静音WAV，不证明实际听感或设备路由；物理显示/输入及未完成目标仍按迁移计划验收。
