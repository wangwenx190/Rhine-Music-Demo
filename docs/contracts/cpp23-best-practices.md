# C++23最佳实践

适用于生产C++、平台适配和原生验证工具。语言与标准库依据为WG21的[C++23最终工作草案N4950](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2023/n4950.pdf)，其版本地位由[编辑报告N4951](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2023/n4951.html)确认；工程原则参考[C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines)。在线资料核对日期为2026-10-17。Core Guidelines由Bjarne Stroustrup、Herb Sutter等维护，是有适用条件的工程建议，并非ISO规范。

下列编号是本项目审查项，不是官方原文编号。RAII、初始化、类型安全、接口、同步和头文件分别对应Guidelines的R、C、ES、F、CP、SF主题；具体检查方法结合本项目的数据、媒体和渲染生命周期制定。标准有效不等于工程合适，采用C++23也不要求使用每一种新语法。

## 所有权与生命周期

- **CPP-01 资源由类型管理。** 列出文件、线程、堆对象、GPU句柄、连接和回调的取得/移交/释放点。值成员优先；独占动态资源用`unique_ptr`，确有共同所有者才用`shared_ptr`。检查提前返回与部分初始化失败。Qt父子树等框架所有权见[Qt实践](qt-best-practices.md)，不得叠加第二个所有者。
- **CPP-02 观察关系有有效期。** 裸指针、引用、迭代器和视图默认不拥有对象。保存元素地址不能越过容器替换、detach、扩容、erase或模型reset；异步使用快照内元素时，应同时保存快照所有者。每个借用接口应能回答由谁保证有效期。
- **CPP-03 析构顺序覆盖依赖。** 成员按声明逆序销毁；worker、engine、window或render对象仍可回调时，被引用状态必须还活着。退出先停止新工作，再结束在途工作，最后销毁依赖。Review的栈变量也适用。
- **CPP-04 回调捕获逐项检查。** 核对`this`、引用、裸指针、视图及间接成员；捕获`shared_ptr`不保护其内部借用对象，连接context也不保护其他捕获对象。沿成功、取消、替换、关闭和队列延迟分别推演。
- **CPP-05 特殊成员保持资源语义。** 普通值类型优先Rule of Zero。自定义析构、复制或移动时审查完整特殊成员及自赋值；资源包装器不可无意复制。除需要复制/移动的值类型外，对象、资源/租约所有者通过`Q_DISABLE_COPY_MOVE`显式禁用复制和移动；只需移动时用`Q_DISABLE_COPY`并显式声明所需移动操作。通过基类删除对象必须有适当虚析构。
- **CPP-06 移动后重建使用前提。** `std::move`不是性能开关；检查所有后续分支中的读取。返回局部值不额外move，对const对象move通常仍复制。声明移动操作`noexcept`前核对全部子操作，不能用承诺隐藏失败。

## 类型、接口和数据边界

- **CPP-07 创建时状态有效。** 标量和状态成员有明确初值；构造完成建立不变量。反例是计数器未初始化即参与分配，或初值读取尚未构造的后置成员。可失败创建用明确结果，不发布半成品。
- **CPP-08 接口表达意图。** 小标量按值，昂贵只读值按const引用，结果优先值返回。命名类型/参数区分ID、状态、时间与空间单位；多字段领域记录优先具名struct，避免std::pair/QPair/std::tuple的位置语义；单参数构造是否允许隐式转换有明确理由，重写写`override`。无派生需求的类和结构体声明`final`；抽象接口、实际基类及Qt注册时生成派生包装的类型保留派生能力；默认可构造的foreign类型即使`QML_UNCREATABLE`也可能需要该包装，不能仅按QML可创建性判断。
- **CPP-09 缺失与失败不伪装成有效值。** `optional`表达可有可无，需要失败原因时用已有错误结果或`expected`。访问前检查缺失；不能让`0`同时表示正常数值和转换失败。空数据、错误、取消和陈旧结果按业务协议区分。
- **CPP-10 视图不延长寿命。** `span`、字符串视图及ranges视图的底层对象必须存活；返回值不得借用局部/临时容器。惰性view还要核对谓词捕获。异步任务通常交接值快照，而非借用调用者缓冲区。
- **CPP-11 转换前验证数字。** 外部JSON/文件/CLI数值先检查有限性、整数性、范围、符号与单位，再转换/分配；小数或超范围值不得变为合法索引。乘法分配尺寸先防溢出，窄API类型只在边界显式转换。
- **CPP-12 索引和枚举有域。** 检查空集合、负索引、长度及跨容器身份；符号转换不能把负值变成巨大尺寸。封闭状态优先`enum class`，外部整数转枚举前验证。`to_underlying`只取表示值，不校验域。
- **CPP-13 字节操作有布局依据。** `memcpy`、`bit_cast`、重解释和平台ABI适配核对对象表示、可平凡复制性、对齐与长度；不得强转绕过对象寿命。shader uniform偏移及native handle留在适配边界验证。
- **CPP-14 不变量由窄接口维护。** 默认只读，不公开可变容器或成组多义布尔参数。用命名操作同步维护值、索引、revision、缓存和通知；调用者不应记住“修改后再手工刷新”。

## 错误与提交

- **CPP-15 失败到达调用者。** 检查open/read/write/commit、资源create、解码和异步完成结果。自有接口在丢弃结果会丢失错误时考虑`[[nodiscard]]`；显式忽略有理由。Release外部输入验证不能仅靠assert。
- **CPP-16 候选值验证后提交。** 解析、索引和资源准备完成后一次发布一致状态。失败保留旧可用状态或进入明确错误态；不能先清库再发现新库不可读，也不能只更新数据而漏更新版本。
- **CPP-17 异常止于可处理边界。** 析构/释放不向外抛；`noexcept`与真实操作匹配。Qt信号槽、事件和渲染回调不能依赖异常穿越框架栈，应转成既定失败协议；吞掉所有异常后报告成功不可接受。[Qt异常边界](https://doc.qt.io/qt-6/exceptionsafety.html)
- **CPP-18 取消后仍验证结果。** 取消不是回滚或回调消失保证。接纳前检查request ID、entity ID与generation；旧失败不得覆盖新成功。持久化失败、设备失效和用户取消保持可区分。

## 并发、复杂度和缓存

- **CPP-19 共享状态有同步协议。** 同一对象的并发读写必须同步；不可变快照可交接。用作用域锁，检查锁顺序；锁内不调用未知回调、不等待GUI、不做慢I/O。`const`和安全引用计数不代表内部线程安全。
- **CPP-20 原子保护范围明确。** 原子取消标志或计数只保护自身；关联对象发布仍需相应同步。采用弱内存序前说明它是独立提示还是承载数据发布，不靠偶然执行顺序。
- **CPP-21 重入也是失效边界。** 跨`emit`、用户回调、模型通知和事件循环保存引用/迭代器时，检查是否会重入并替换数据。需要时先保存值/稳定ID，返回后重新查找并检查generation。
- **CPP-22 复杂度沿调用链计算。** 循环中的查找、排序、序列化和文字测量要结合规模与频率；N次线性查找形成O(N²)不能被短函数掩盖。一次O(N)建索引与逐帧O(N)处理区别对待。
- **CPP-23 等待与完成也有上界。** 限制worker数量之外，还需限制等待队列、取消记录、完成邮箱、缓存和重试。重复输入合并或淘汰旧工作；不能把积压转移成无限queued callback。
- **CPP-24 缓存覆盖全部依赖。** 核对同ID内容变化、字体数据库、尺寸/DPR、失败重试和重建；key/revision包含实际影响结果的输入。替换/淘汰更新字节计数，缓存不延长无用业务对象寿命。
- **CPP-25 容器和算法服务实际访问。** 优先已有Qt/标准算法，批量处理后提交。频繁按ID查询用索引；不为一个字段序列化全库。reserve减少扩容，不能修复错误复杂度。

## C++23、源码和验证

- **CPP-26 新设施解决具体问题。** `expected`表达值/错误，optional monadic操作串联缺失值，`to_underlying`明确枚举表示；采用前确认三平台标准库支持。设计依据：[expected](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2022/p0323r12.html)、[optional monadic操作](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2021/p0798r8.html)、[to_underlying](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2021/p1682r3.html)；最终语义以C++23草案为准。
- **CPP-27 不以语法替代架构。** ranges不自动减少遍历，协程不自动提供线程/取消，modules不自动适配moc和部署。已有清晰Qt接口不为语法更新无收益重写；采用时补齐寿命、失败和工具链闭包。
- **CPP-28 头文件自包含。** 自有头文件直接提供公开声明的依赖或合法前置声明；不依赖碰巧的传递include，不在公共头全局`using namespace`。避免循环依赖及跨翻译单元重复定义。仅借用的类型优先前置声明，完整定义放到实现文件；moc需要完整属性类型时使用`Q_MOC_INCLUDE`。线程、watcher、缓存等实现依赖重且生命周期稳定的服务使用`unique_ptr<Private>` pimpl，构造/析构在实现文件定义，保持退出协议和成员销毁顺序；小型数学/帧快照保留值布局，不为隐藏字段引入热路径分配。
- **CPP-29 平台分支真实可用。** 核对条件编译下类型、整数宽度、路径编码、API错误和释放。主机编译不证明其他平台分支正确；版本、Kit发现和能力探针唯一见[native-bootstrap.md](native-bootstrap.md)。
- **CPP-30 ASCII源码与显式字符串类型。** 按用户要求，C++/QML源文件只含ASCII英文；界面源文案为英文并进入Qt翻译系统，其他语言放翻译资源。emoji及Unicode测试输入写转义，业务数据不按界面文案翻译。QString字面量用`u"..."_s`，需要Latin-1视图时用`"..."_L1`，QByteArray字面量用`"..."_ba`；动态字节默认UTF-8，禁止`QStringLiteral`、`fromLatin1`/`toLatin1`和隐式ASCII转换。该选择是项目契约，Qt仍支持其他编码API。[Qt字符串字面量](https://doc.qt.io/qt-6/qt-literals-stringliterals.html)
- **CPP-31 检查覆盖真实风险。** 所有权、数值边界、取消/替换、退出及事务失败使用能触发问题的测试；低风险可逆修改不堆同构测试。编译警告、静态分析、功能回归与目标实机事实分别报告。

## 注释、命名数值与静态初始化

- **CPP-32 英文解释职责与原理。** 自有头文件开头简述设施作用、机制和关键寿命边界；复杂算法、状态转换、异步取消/交接、资源布局及平台适配就近解释不变量、单位和设计依据。注释使用纯英文，随代码更新；不逐句复述显而易见的语法。
- **CPP-33 策略数值必须命名。** 时序、阈值、容量、来源视觉参数、协议布局和容差使用含义清晰、作用域最小的`constexpr`数值或非限定枚举；必要时说明来源、单位或公式。零/单位元、直接表达数学结构的系数、具名数据记录及独立测试的显式输入/期望值不等于策略魔数，不为这些数值制造无意义别名。QML使用具名只读属性，shader使用`const`，脚本使用对应语言的具名常量；不得用数字拼出的名字或无关数值共享替代语义命名。同一领域参数或算法跨文件使用时，抽到最小职责的公共头、类、函数或模块；跨QML/C++边界通过类型化接口复用，shader通过公共include或唯一生成源复用。测试独立的输入/期望值不从被测实现反向生成，框架语法与不同语义的零/单位元不放入通用字面量池。
- **CPP-34 禁止复杂全局对象。** 命名空间和类静态存储只保留C++字面类型与Qt宏生成设施；需要容器、曲线、锁或其他运行时构造对象时，使用函数级静态对象或`Q_GLOBAL_STATIC`，并审查首次调用、并发和退出顺序。常量数据优先`constexpr`，对象必须在使用它的回调前构造并活到回调结束。字符串类型按实际消费接口选择；固定Latin-1常量与静态表可使用`constexpr QLatin1StringView`，需要拥有型字符串时直接使用对应字面量，避免重复视图转换。能否常量求值由当前Kit和编译器实际确认，不能常量求值的拥有型固定对象使用`const`或函数级`static const`。

- **CPP-35 控制流保持浅层并按职责分派。** 业务条件最多嵌套两层；前置条件用守卫返回/continue，独立阶段拆成具名操作。禁止长if-else链和巨型switch；同一输入的离散映射、状态/角色/命令分派优先静态表，按需执行选中操作，不预构造全部结果，不在帧路径分配闭包表。lambda只作短小适配（通常不超过20行），可调用已有lambda，禁止在lambda体内声明另一个lambda；复杂回调提取为具名函数或成员操作，显式保持context、捕获对象寿命、线程及取消协议。不得仅以增加转发层或隐藏分支满足形式限制。

## 审计入口与专项职责

`python3 tools/audit/audit-best-practices.py --output verification/全新目录`读取Release compile database，输出实际编译单元的hash和所选clang-tidy诊断。[clang-tidy官方说明](https://clang.llvm.org/extra/clang-tidy/index.html)界定工具能力；`compilerChecksClean`仅表示所列检查无诊断，不能证明架构、未编译分支或全项目语义正确。

人工审查关联文件/符号、调用者、状态前提、失败/取消/销毁路径、判定与局限；文件清单、规则命中数和少量示例不能代表完整覆盖。格式见[code-style.md](code-style.md)，性能上界见[performance.md](performance.md)，验证选择见[test-gates.md](test-gates.md)，不在此重复维护数值和门槛。
